二、数据库操作

提示：必须先 USE 库名（或用 -D 指定），建表才会建在这个库里。

三、建表 CREATE TABLE

1. 字段规则

类型 说明
VARCHAR(n) 字符串，n 是最大字符长度
INT 整数，上限约 21 亿，海量数据用 BIGINT
datetime 时间类型，不写长度
  • NOT NULL：字段不能为空，不写则允许 null
  • AUTO_INCREMENT：主键自增，从 1 开始
  • PRIMARY KEY：主键，非空且唯一，用来唯一标识一行数据

2. 末尾配置

  • ENGINE=InnoDB：MySQL 默认存储引擎
  • DEFAULT CHARSET=utf8：字符编码

3. 符号规则

规则 说明
全部英文符号 ❌ 中文逗号、中文括号会报错
反引号 ` 包裹表名 / 字段名 和单引号 ' 区分，编辑器高亮的关键字用作名称时必须套反引号
字段间逗号分隔 最后一个字段后不加逗号
语句末尾 ; 漏写会卡住

四、删表 DROP TABLE

  • IF EXISTS：表存在才删，不存在不报错
  • 删除后表和数据全部清除，不可逆，谨慎操作 ⚠

易错点 正确做法

九、LIMIT 限制返回行数

LIMIT 用来限定返回多少行数据，常用于分页。数据库行号从 0 开始计数。

1. 写法 1：LIMIT n 查询前 n 行

等价写法：SELECT * FROM timi_adc LIMIT 0, 5;

含义：取第 0~5 行，一共 5 条记录。

2. 写法 2：LIMIT offset, count 查询第 x-y 行

  • 第一个参数 offset：偏移量，从 0 开始，代表跳过多少行
  • 第二个参数 count：本次一共查询多少条记录

含义：跳过 5 行，从第 6 行开始，一共查询 6 条记录（查询第 6-11 行）。

含义：查询表第 5 行的数据。

3. LIMIT 和 WHERE 联合使用

提示：LIMIT 必须写在 WHERE 的后面。

示例：查询 timi_adc 表登场率大于 10% 的前 5 条数据

datetime 时间 过去 → 现在

2. DESC 降序（逆序）

DESC：从大到小逆序排列。

3. 和 LIMIT 联合使用

十六、多表关联查询

1. JOIN 分类

类型 关键字 返回结果
内连接 INNER JOIN / JOIN 两表同时满足条件的数据（交集）
左外连接 LEFT JOIN 左表全部数据 + 右表匹配数据，右表匹配不到填 NULL
右外连接 RIGHT JOIN 右表全部数据 + 左表匹配数据，左表匹配不到填 NULL
笛卡尔积 CROSS JOIN 两表数据的单纯乘积，实际应避免

LEFT JOIN 和 RIGHT JOIN 都属于外连接，和内连接对应。

2. INNER JOIN 内连接（交集）

语法：

  • INNER 可以省略，只写 JOIN 效果一样
  • 返回两表同时满足条件的数据，即交集

3. LEFT JOIN 左连接

语法：

规则：返回左表 TableA 全部数据；右表 TableB 匹配不到的数据，右表字段全部填充 NULL。

示例：全部老师都显示，就算老师没有排课也要展示。左表 ykd_teacher，右表 ykd_course。

要点 说明
左表位置 写在 FROM 后面
右表位置 写在 LEFT JOIN 后面
关联条件 写在 ON 后面，不要写在 WHERE 里
左表数据 全部保留
右表匹配不上 右表字段全部为 NULL

4. RIGHT JOIN 右连接

语法：

规则：和 LEFT JOIN 对称，返回右表全部数据；左表匹配不到的数据，左表字段全部填充 NULL。

提示：LEFT JOIN 和 RIGHT JOIN 可以互相转换，把两张表换个位置就行。实际开发中 LEFT JOIN 更常用。

5. LEFT JOIN + IS NULL（A 中与 B 无关的数据）

需求：查询 A 表中和 B 表完全没有关系的数据（A 的独有部分，排除交集）。

原理：LEFT JOIN 后，B 表匹配不到的字段为 NULL，用 WHERE ... IS NULL 筛选出这些行。

6. 三张及以上表 LEFT JOIN

规则：选一张表作为主表写在 FROM 后，其余表依次 LEFT JOIN ... ON，统一用 LEFT JOIN，不要混 RIGHT JOIN。

语法：

7. UNION 合并查询结果

UNION 将两个查询语句的结果合并，并去除重复数据。

上面的写法相当于同时执行左右连接，得到 A∪B 全部数据。

关键字 作用
UNION 合并并去重
UNION ALL 合并不去重
UNION DISTINCT 和 UNION 等价，一般直接写 UNION

8. CROSS JOIN 笛卡尔积（了解即可）

结果是两表数据的单纯乘积（A 有 2 条、B 有 3 条 → 2×3=6 条）。

  • 实际应用中应该避免，只需知道概念
  • MySQL 中 INNER JOIN、CROSS JOIN、JOIN 是等价的
  • 一般 INNER JOIN 配合 ON 使用，CROSS JOIN 配合其他条件使用

9. 多表查询完整顺序

顺序 关键字 说明
1 SELECT 查什么字段
2 FROM 主表
3 JOIN ... ON 关联表 + 关联条件
4 WHERE 条件过滤
5 ORDER BY 排序
6 LIMIT 限制行数

2. DELETE / DROP / TRUNCATE 区别

操作 作用 表结构 可恢复

十九、高频易错清单

序号 易错点 正确做法
1 表名/字段名用错引号 表名/字段用反引号 `，字符串值用单引号 '
2 建表最后字段多加逗号 最后一个字段后面不能写逗号
3 UPDATE / DELETE 忘写 WHERE 不写 WHERE 会修改/删除全表，非常危险
4 DROP 操作不可逆 删库删表前确认，删除后无法恢复
5 AND / OR 优先级混乱 AND 优先级高于 OR，复杂条件加小括号 ()
6 IN / NOT IN 括号省略 括号不能省略，值之间用逗号分隔
7 用 = NULL 判断空值 ❌ = NULL → ✅ IS NULL / IS NOT NULL
8 CONCAT 拼接参数含 NULL 只要一个参数为 NULL，拼接结果整体为 NULL
9 TRIM 处理中间字符 TRIM 只能处理首尾，不能删除中间字符
10 JOIN 关联条件写 WHERE 关联条件写 ON，不要写 WHERE
11 INNER / LEFT / RIGHT 搞混 INNER JOIN 取交集；LEFT JOIN 左表全保留；RIGHT JOIN 右表全保留
12 LEFT JOIN + IS NULL 写错字段 WHERE 后面判断的是右表的关联字段 IS NULL
13 多表查询混写 RIGHT JOIN 三张及以上表统一用 LEFT JOIN，选一张主表依次关联
14 UNION 和 UNION ALL 不分 UNION 去重，UNION ALL 不去重
15 笛卡尔积实际应避免 写 JOIN 一定要带 ON 条件，否则产生笛卡尔积
16 LIMIT 偏移从 1 开始数 行号从 0 开始，LIMIT 0, 5 = 前 5 条
17 SELECT 子句顺序写错 FROM → JOIN ... ON → WHERE → ORDER BY → LIMIT
