Spring Web 全栈知识点归纳

一、Maven 核心知识点

1. 项目自身坐标（定义本项目）

Maven 通过坐标唯一标识一个项目，由三要素组成：

标签 说明
<groupId> 组织/公司
<artifactId> 项目名称
<version> 版本号

  • version 区分 ：SNAPSHOT（快照版）、正式发行版

  • 打包方式 <packaging> ：jar（默认）、war

2. properties 属性标签

统一定义版本号、编码格式，多处复用，方便统一修改。

3. dependencies 依赖管理

  • 一个 pom 只能有有有一个有有 dependencies，内部多个 dependency

  • 查找顺序 ：本地 .m2 仓库 → 远程中央仓库下载

  • 仓库搜索 ：阿里云 maven 镜像（国内推荐）

术语

：

术语 说明
二方库 团队内部代码包
三方库 外部开源组件
传递依赖 A 依赖 B，B 依赖 C → A 自动持有 C 依赖

4. build / plugins 插件体系

  • 插件本质也是 jar 包，用来增强 Maven 功能（编译、打包等）

  • 示例：maven-compiler-plugin 负责编译 Java 代码

5. 基础补充

  • 标签全部为 XML 格式，严格区分大小写、闭合标签

  • 本地仓库路径：用户目录下 .m2

  • 依赖坐标 = groupId + artifactId + version（唯一标识 jar 包）

二、Spring HelloWorld 注解开发

1. Bean 概念

  • Bean ：Spring IoC 容器管理的 Java 对象

  • 开发模式 ：接口 + 实现类，直接从容器拿 Bean，不用自己 new 实现类

  • 容器顶层接口 ：ApplicationContext

  • 注解版 IoC 容器实现类 ：AnnotationConfigApplicationContext

2. Spring 核心依赖

💡 理念 ：Spring 提倡倡倡面向接口编程倡倡，业务代码通常由接口 + 实现类组成。

3. 核心注解 @ComponentScan

作用

：自动扫描 Bean

  • 写在 Spring 配置类上面

  • Spring 自动扫描当前配置类所在包及其全部子包

  • 识别带有 @Service、@Component、@Repository、@Controller 标记的类

  • 自动实例化对象存入 IoC 容器

⚠ 注意 ：@ComponentScan 不写，Spring 不会自动创建 @Service 标记的类。

优势

：开发人员无需手动 new 对象，交给 Spring 统一管理。

4. 四个 Bean 注解

注解 使用位置 用途
@Component 普通类 通用注解，另外 3 个都是基于它扩展
@Service 业务层实现类 业务 service 层使用
@Controller web 控制器类 web 层用
@Repository 数据库操作类 持久层用

⚠ 注意 ：写在类上，接口不加注解！

@Service 使用规范

：

标记位置 说明
✅ service 实现类（SongServiceImpl） 加在实现类上
❌ service 接口 不要加在接口上
❌ model 实体类 不要加在实体类上

七、Spring Bean 生命周期 @PostConstruct

1. Bean 完整生命周期流程

阶段 说明
实例化 Bean Spring 调用构造方法，创建对象
完成依赖注入 给对象的属性、@Autowired 成员赋值
afterPropertiesSet() 接口方式初始化
@PostConstruct 初始化方法 依赖注入完成后自动执行
Bean 使用 业务代码正常运行
destroy 销毁 容器关闭时执行销毁逻辑

执行顺序

：实例化 → 依赖注入 → afterPropertiesSet → @PostConstruct 初始化 → Bean 使用 → destroy 销毁

2. 重点注解 @PostConstruct

  • 包路径 ：javax.annotation.PostConstruct

  • 作用 ：依赖注入全部完成之后，自动执行该方法，做初始化工作

  • 方法名可以随便取，不一定叫 init；无返回值，无参数

3. 业务场景

把原来 static {} 静态代码块的初始化逻辑迁移到 @PostConstruct 方法。

方式 执行时机 能否使用注入的成员变量
static {} 静态代码块 类加载时执行 否，此时还没有 Spring 依赖注入
@PostConstruct Spring 完成依赖注入之后 能，可以使用 @Autowired 注入好的成员变量

4. 简答背诵版

Spring Bean 生命周期：实例化对象 → 依赖注入 → 初始化方法 → 使用 Bean → 销毁。

@PostConstruct 标注的方法，在依赖注入完成后自动执行，用于 Bean 初始化，适合加载初始数据。包名 javax.annotation.PostConstruct。

八、Spring MVC Controller

1. Controller 页面跳转基础

@Controller

标记类为控制器，Spring 扫描识别，用来处理 web 请求。

@RequestMapping(“/路径”)

  • 作用：绑定 URL 访问路径，默认接收所有 HTTP 请求方式（GET/POST）

  • 返回字符串：代表 static 下 html 页面路径，实现页面跳转

@GetMapping(“/路径”)

专门只接收 GET 请求，替代 @RequestMapping，更安全。

访问多参数 url 格式：url?key1=值&key2=值，& 分割多个参数；参数顺序和代码形参顺序无关。

2. @RequestParam 获取 URL 查询参数

语法：@RequestParam("参数名") 类型 变量名

基础必传参数

  • 注解内名字必须和 url 问号后的参数 key 完全一致

  • 默认 required=true：参数必须传，不传直接 400 报错

非必传参数 required = false

可以不传该参数，两种 url 都合法。

⚠ 基础类型 int 不要用，不传值会 null 报错，优先用包装类 Integer。

多参数获取：方法参数位置写多个 @RequestParam，Spring 自动完成 String int boolean 类型转换。

3. @ResponseBody 输出 JSON，编写 API 接口

场景 行为
不加 @ResponseBody 返回值当做 html 页面路径，跳转页面
加上 @ResponseBody 不跳转页面，直接把内容输出到浏览器，用于后端 API

返回字符串

返回 Java 实体对象

⚠ 实体类必须提供 getter/setter，缺少 getter JSON 转换失败。

@PostConstruct

写在方法上：Bean 对象创建完成之后，Spring 自动执行该初始化方法，用于模拟加载测试数据。

4. 注解速查表

注解 核心作用
@ComponentScan 开启包扫描，自动注册 Bean
@Controller 标记 web 控制器类
@RequestMapping 绑定 url，接收全部 http 请求
@GetMapping 绑定 url，只接收 GET 请求
@RequestParam 获取 url? 后的查询参数，required=false 非必传
@ResponseBody 返回 JSON，不跳转 html，写 API 接口

十一、Spring Boot 包扫描机制

1. 核心原理

@SpringBootApplication 注解的类是启动类，，，默认只扫描启动类所在的包，以及它下面所有的子包，，。

2. 为什么会找不到 Bean？

举例：启动类在 fm.douban.app 包，Service 实现类在 fm.douban.service.impl 包，这两个包是是是平级关系是是，不是父子关系：

包路径 是否扫描 原因
fm.douban.app ✅ 启动类所在包
fm.douban.app.xxx ✅ 子包
fm.douban.service ❌ 平级包
fm.douban.service.impl ❌ 更不会被扫描

Service 实现类没被扫到 → Spring 容器里没有这个 Bean → 注入时报 NoSuchBeanDefinitionException。

3. 解决办法一：scanBasePackages

在启动类的 @SpringBootApplication 上加参数，指定要额外扫描的包：

  • 参数名：scanBasePackages

  • 参数值：字符串数组，把所有需要扫描的包都写进去

4. 解决办法二：@ComponentScan

如果不是启动类，可以用独立的 @ComponentScan 注解，效果一样：

这个不太常用，但要知道有这个东西。

5. 补充：@RestController

@RestController 等价于 @Controller + @ResponseBody（加在类上，所有方法都生效）：

注解 方法返回值 用途
@Controller 返回视图名（跳转页面） 做页面跳转、Thymeleaf 渲染
@RestController 直接返回数据（JSON） 做接口、前后端分离

图书管理项目用的是 @Controller + Thymeleaf 页面，不能改成 @RestController，不然所有方法都不渲染页面了。

6. 一句话总结

Spring Boot 默认只扫启动类所在包及其子包，平级包扫不到。扫不到 → 没有 Bean → 注入报错。解决：scanBasePackages 把要扫的包都写上。

好处：开发的时候开 debug，看所有信息；上线的时候改成 info 或 error，只看重要的，不用改代码。

十四、Spring Session 完整指南

1. Session 基础

核心概念

要点

：

  • Session 是服务器端的会话存储，每个用户对应一个独立的 Session 对象

  • 浏览器通过 Cookie 中的 JSESSIONID 标识自己，服务器根据该 ID 找到对应用户的 Session

  • Session 数据存在服务器，用户无法直接查看或修改，，，安全性高于 Cookie，， ✅

工作流程

  1. 用户首次访问 → 服务器创建 Session，生成唯一 JSESSIONID
  2. 服务器通过响应头 Set-Cookie: JSESSIONID=XXX 将 ID 写入浏览器
  3. 后续请求浏览器自动携带该 Cookie
  4. 服务器根据 JSESSIONID 定位 Session，读写其中的数据

7. Session 与 Cookie 对比

对比项 Cookie Session
存储位置 浏览器端 服务器端
安全性 低，用户可查看修改 高，用户无法直接访问

一句话理解

：Cookie 是浏览器存的小纸条，Session 是服务器存的档案袋，JSESSIONID 就是档案编号，浏览器每次带着编号来取档案。
