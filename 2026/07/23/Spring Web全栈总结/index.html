Spring Web 全栈知识点归纳

一、Maven 核心知识点

1. 项目自身坐标（定义本项目）

Maven 通过坐标唯一标识一个项目，由三要素组成：

标签 说明
<groupId> 组织/公司
<artifactId> 项目名称
<version> 版本号
  • version 区分：SNAPSHOT（快照版）、正式发行版
  • 打包方式 <packaging>：jar（默认）、war

2. properties 属性标签

统一定义版本号、编码格式，多处复用，方便统一修改。

3. dependencies 依赖管理

  • 一个 pom 只能有一个 dependencies，内部多个 dependency
  • 查找顺序：本地 .m2 仓库 → 远程中央仓库下载
  • 仓库搜索：阿里云 maven 镜像（国内推荐）

术语：

术语 说明
二方库 团队内部代码包
三方库 外部开源组件
传递依赖 A 依赖 B，B 依赖 C → A 自动持有 C 依赖

4. build / plugins 插件体系

  • 插件本质也是 jar 包，用来增强 Maven 功能（编译、打包等）
  • 示例：maven-compiler-plugin 负责编译 Java 代码

5. 基础补充

  • 标签全部为 XML 格式，严格区分大小写、闭合标签
  • 本地仓库路径：用户目录下 .m2
  • 依赖坐标 = groupId + artifactId + version（唯一标识 jar 包）

二、Spring HelloWorld 注解开发

1. Bean 概念

  • Bean：Spring IoC 容器管理的 Java 对象
  • 开发模式：接口 + 实现类，直接从容器拿 Bean，不用自己 new 实现类
  • 容器顶层接口：ApplicationContext
  • 注解版 IoC 容器实现类：AnnotationConfigApplicationContext

2. Spring 核心依赖

💡 理念：Spring 提倡面向接口编程，业务代码通常由接口 + 实现类组成。

3. 核心注解 @ComponentScan

作用：自动扫描 Bean

  • 写在 Spring 配置类上面
  • Spring 自动扫描当前配置类所在包及其全部子包
  • 识别带有 @Service、@Component、@Repository、@Controller 标记的类
  • 自动实例化对象存入 IoC 容器

⚠ 注意：@ComponentScan 不写，Spring 不会自动创建 @Service 标记的类。

优势：开发人员无需手动 new 对象，交给 Spring 统一管理。

4. 四个 Bean 注解

注解 使用位置 用途
@Component 普通类 通用注解，另外 3 个都是基于它扩展
@Service 业务层实现类 业务 service 层使用
@Controller web 控制器类 web 层用
@Repository 数据库操作类 持久层用

⚠ 注意：写在类上，接口不加注解！

@Service 使用规范：

标记位置 说明
✅ service 实现类（SongServiceImpl） 加在实现类上
❌ service 接口 不要加在接口上
❌ model 实体类 不要加在实体类上

5. 启动 IoC 容器（2 种构造方法）

容器启动后：加载资源 → 实例化加了 Bean 注解的 Java 对象，存入容器。

7. 完整运行流程

  1. 运行 main 方法
  2. 创建 Spring 上下文，读取配置类上 @ComponentScan
  3. 根据包路径扫描，找到标记 @Service 的 MessageService 实现类
  4. Spring 自动实例化对象，存入 IoC 容器
  5. getBean() 从容器取出实例（传接口，自动找实现类）
  6. 调用 getMessage() 方法，打印输出

8. 必背易错点

易错点 正确做法
接口加 @Service ✅ 打在实现类上，不要加在接口上
getBean 传实现类 ✅ 传接口 .class，Spring 自动找实现类
不写 @ComponentScan ✅ 必须配置，否则 Spring 找不到带注解的类，不会创建 Bean
四个注解功能是否不同 底层都是 @Component，只是语义区分，功能一样
直接 getBean 不启动容器 ✅ 一定要先启动 IoC 容器，才能 getBean 拿对象

三、Java 注解（Annotation）

1. 元注解（定义注解的注解）

@Target

限制注解标注位置，取值来自 ElementType 枚举：

枚举值 说明
TYPE 类、接口、枚举
FIELD 成员变量
METHOD 方法
PARAMETER 方法参数

@Retention

定义注解生命周期，取值 RetentionPolicy：

枚举值 说明
SOURCE 仅源码有效，编译消失
CLASS 存入 class 文件，运行失效（默认）
RUNTIME 运行时有效，自定义注解必写 ⚠

@Documented

生成 JavaDoc 文档时保留注解信息。

@interface

自定义注解固定开头语法，代表这是注解。

注解属性：

特性 说明
value 默认属性，可简写
default 设置默认值
@AliasFor 设置属性别名

2. 万能标准模板（直接默写）💡

3. 补充特性

  • 注解可嵌套组合使用
  • 注解需要导包
  • Spring 的 @Service、@Component 就是用这套注解机制实现 Bean 扫描（与第二节 @ComponentScan 关联）

四、Spring 依赖注入（@Service + @Autowired）

1. 两个核心注解

注解 作用 位置
@Service 把类标记为 Spring 的 Bean，交给 IoC 容器创建管理 服务实现类上
@Autowired 自动从 Spring 容器中找到对应 Bean，赋值给成员变量 成员变量上
  • @Autowired 完整包：org.springframework.beans.factory.annotation.Autowired
  • 没有 @Service，这个类不会变成 Bean，就不能被注入

4. ⚠ 两个缺一不可的条件

条件 说明

少任意一个，注入失败，变量为 null，调用方法报空指针。

5. 执行流程

  1. Spring 容器启动，@ComponentScan 扫描包
  2. Spring 把所有带 @Service 的类实例化成 Bean 放入容器
  3. 遇到 @Autowired，去容器找对应接口的 Bean，自动赋值给成员变量
  4. 业务代码直接使用该变量，不需要手写 new、set

6. 接口小重点

7. 易错坑

易错点 正确做法
@Autowired 加了，但实现类没写 @Service ✅ 实现类必须加 @Service，否则注入失败
接口上写 @Service ✅ 注解打在实现类，不写在接口
自己 new 实现类对象 ✅ 必须启动 Spring IoC 容器，依赖注入才生效；自己 new，@Autowired 不会工作

五、Spring Resource 资源读取

1. 三种文件位置

位置 示例 读取方式
电脑磁盘绝对路径 d:/mywork/a.doc 直接用 File 读取
工程根目录 mywork/toutiao.png 直接用 File 读取
src/main/resources 下 data.json ⚠ 打包成 jar 后不能用 File

⚠ 重点：Maven 打包后，src/main/resources 下的文件会被打进 jar 压缩包内部，不是磁盘上真实独立文件，不能用 File 读取。

2. classpath（类路径）

  • classpath 是虚拟目录，根目录 / 等价于 src/main/resources + src/main/java 编译之后的根位置
  • jar 包解压后，看不到 src/main/resources 这一层文件夹，资源文件直接放在 jar 包根下
  • classpath 资源不能转为 File 对象，只能拿到 InputStream 字节流

3. 读取 classpath 资源核心代码

⚠ 路径直接写文件名，不要写 src/main/resources/。

七、Spring Bean 生命周期 @PostConstruct

1. Bean 完整生命周期流程

阶段 说明
实例化 Bean Spring 调用构造方法，创建对象
完成依赖注入 给对象的属性、@Autowired 成员赋值
afterPropertiesSet() 接口方式初始化
@PostConstruct 初始化方法 依赖注入完成后自动执行
Bean 使用 业务代码正常运行
destroy 销毁 容器关闭时执行销毁逻辑

执行顺序：实例化 → 依赖注入 → afterPropertiesSet → @PostConstruct 初始化 → Bean 使用 → destroy 销毁

2. 重点注解 @PostConstruct

  • 包路径：javax.annotation.PostConstruct
  • 作用：依赖注入全部完成之后，自动执行该方法，做初始化工作
  • 方法名可以随便取，不一定叫 init；无返回值，无参数

3. 业务场景

把原来 static {} 静态代码块的初始化逻辑迁移到 @PostConstruct 方法。

方式 执行时机 能否使用注入的成员变量
static {} 静态代码块 类加载时执行 否，此时还没有 Spring 依赖注入
@PostConstruct Spring 完成依赖注入之后 能，可以使用 @Autowired 注入好的成员变量

4. 简答背诵版

Spring Bean 生命周期：实例化对象 → 依赖注入 → 初始化方法 → 使用 Bean → 销毁。

@PostConstruct 标注的方法，在依赖注入完成后自动执行，用于 Bean 初始化，适合加载初始数据。包名 javax.annotation.PostConstruct。
